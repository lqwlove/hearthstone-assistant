## Context

仓库几乎为空（README + OpenSpec），无既有应用代码。动机与范围见 `proposal.md`。约束已在探索中锁定：React + FastAPI、暴雪官方 API、JWT 简单账号、简中、标准/狂野、组牌专页三栏、服务端统一 LLM Key、助手自由对话且可选结构化改套。

## Goals / Non-Goals

**Goals:**
- 建立前后端可运行骨架与数据模型，支撑认证、卡牌同步/查询、卡组草稿与最终保存、组牌页与助手对话
- 明确官方 API 同步边界、校验引擎职责、以及助手「可选 patch」协议形状
- 让 PC 宽屏信息架构与 API 边界对齐，便于按 tasks 增量实现

**Non-Goals:**
- 不在本设计中选定具体 CSS 框架或组件库品牌
- 不实现收藏/尘、记牌器、分享社区、多助手会话
- 不解决暴雪 API 全部边缘卡组规则（侧次职业等），只预留扩展点

## Decisions

### D1: 单体后端 + SPA 前端
- **选择**: FastAPI 提供 REST（及必要时的同步管理接口）；React SPA 消费 API。
- **理由**: 团队已选定栈；MVP 无需微前端/多服务。
- **备选**: Next.js 全栈——与「FastAPI」决策冲突，放弃。

### D2: 数据库用 PostgreSQL（开发可用 SQLite 切换）
- **选择**: 生产取向 PostgreSQL；本地可通过配置改用 SQLite 以便快速启动。
- **理由**: 用户卡组、对话、卡牌目录需要关系查询；SQLAlchemy/类似 ORM 易切换方言。
- **备选**: 纯 Mongo——卡牌与校验更适合关系约束，不取。

### D3: 卡牌同步为后端批处理，前端只读本地目录
- **选择**: 服务端持有 Blizzard Client ID/Secret，拉取 `zh_CN` 卡牌与元数据写入本地表；提供手动同步入口（管理员或受保护的运维接口即可）。前端牌库/牌池只查本地 API。
- **理由**: 不暴露暴雪凭证；便于限流、缓存与简中一致性。
- **备选**: 前端直连暴雪——不安全且难控配额。

### D4: 卡组状态 `draft` / `completed`
- **选择**: 草稿任意保存；`completed` 仅在校验通过时写入。允许从 `completed` 再编辑回 `draft`（或编辑时自动降回草稿）。
- **理由**: 匹配「边聊边改」；最终保存是明确的合规门闩。

### D5: 校验引擎纯后端纯函数
- **选择**: 单一 `validate_deck(deck, cards_meta, format)`，最终保存必调；组牌页可另提供「预校验」接口供 UI 展示违规，但不阻止草稿保存。
- **基线规则**: 30 张；职业+中立；同名≤2、传说≤1；模式合法性来自同步元数据。
- **备选**: 仅前端校验——不可信，放弃。

### D6: 组牌页路由与壳层分离
- **选择**: 常规页（牌库、卡组列表、详情、登录）使用带全局导航的壳；`/decks/:id/build` 使用沉浸式三栏壳（顶栏 + 左牌池 + 中操作区 + 右助手）。
- **理由**: 产品明确要求组牌页去掉左侧全局菜单。

### D7: 助手可选 `deck_patch` 协议
- **选择**: LLM 响应主路径为自然语言。约定可选机器可读块（例如 JSON：`{ "ops": [ { "op": "set_count", "card_id": "...", "count": 2 }, ... ] }`），后端若解析成功则应用到草稿；缺失或非法则忽略 patch，保留文本。
- **理由**: 产品要「自由助手」，结构化是能力不是每轮义务。
- **备选**: 强制 tool-call——与已拍板决策冲突。

### D8: LLM 适配层
- **选择**: 后端 `LlmClient` 抽象，配置 `provider=openai|claude`（或兼容 base URL）、统一 API Key；请求由服务端发出。
- **理由**: 一份 Key、两种格式兼容；前端零密钥。

### D9: 认证
- **选择**: 用户名+密码注册/登录；密码哈希（如 bcrypt/argon2）；JWT access token（Bearer）。MVP 不做刷新令牌旋转与 OAuth。
- **理由**: 与「JWT + 简单账号」一致，足够保护卡组与对话。

## Risks / Trade-offs

- **[暴雪 API 字段/标准轮转复杂]** → 同步层集中映射；模式合法性以官方字段为准，单测覆盖映射样例；文档记录已知限制。
- **[助手胡乱改套或不改套]** → patch 可选且校验/预览在 UI 可见；非法 patch 安全忽略；不把助手当作唯一组套路径。
- **[统一 LLM Key 成本与滥用]** → MVP 可接受；后续可加每用户限额或自备 Key。
- **[SQLite/Postgres 双方言差异]** → 避免专有 SQL；迁移用 Alembic（或等价）管理。

## Migration Plan

- 绿场部署：初始化 DB schema → 配置暴雪与 LLM 环境变量 → 首次手动同步卡牌 → 启动 API 与前端。
- 回滚：无生产数据历史；失败则回退部署版本并保留 DB 备份（若已有用户数据）。
